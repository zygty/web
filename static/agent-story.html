整份报告的结构

报告从两个项目展开：先介绍学术网站如何组织文献与支持写作，再介绍航空地图如何展示轨迹与提供预测能力。 最后用一个简短总结说明两部分在航空研究主题中的联系。

Part 01 · 学术网站

Hermes Research Workbench：把论文阅读、证据问答、综述整理和写作支持集中到同一个界面

这一部分对应研究型学术网站，重点展示文献如何被组织、论文如何被结构化呈现，以及系统如何辅助综述与论文写作。

  • 核心模块包括 Literature Library、AI Research Assistant、Literature Review、Writing Workflow。
  • 支持检索论文、读取 chunk、生成 grounded answer、整理综述上下文与论文草稿。
  • 截图中的研究主题与 ADS-B、轨迹分析、trajectory clustering 直接相关。
Part 02 · 航空地图

航空地图：把飞行轨迹展示、时间轴回放与轨迹预测整合成可交互系统

这一部分对应轨迹可视化系统，重点展示地图如何呈现航班分布、动态轨迹、播放控制和预测结果， 适合用于演示航空数据的时空变化。

  • 核心能力包括地图轨迹展示、时间轴播放、多底图切换、状态监控和 LSTM 预测。
  • 页面可以展示高质量航班样本，并为选中的航班叠加未来轨迹。
  • 这一部分更适合展示航空数据如何被转化为一个可视化、可讲解、可交互的系统。

第一部分：学术网站到底在展示什么

这部分展示的是一个研究工作流平台。重点不在单一页面样式，而在它如何围绕论文、chunk、证据与写作结构， 组织出一个能够服务学术研究的工作台。
对应截图里能明确识别出的区块包括：左侧 Literature Library，中部 Selected Literature / Paper Snapshot / Source Preview，右侧 AI Research Assistant、Literature Review、 Writing Workflow 与 Import New PDFs。

学术网站的核心功能

这一部分围绕“文献组织、基于证据的问答、综述生成和论文写作支持”展开，而不是只停留在界面外观。

文献管理

Literature Library

左侧的文献库不仅列出论文，还支持搜索、状态筛选和 tag filter。它让研究主题不再散落在文件夹里， 而是形成一个可检索、可回看的知识底座。

  • 支持 title / author / DOI / tag 等维度检索。
  • 能按状态和主题标签快速切换候选文献。
  • 截图中已有 ADS-B、trajectory 等研究主题标签。
论文视图

Selected Literature + Snapshot

中间区域把单篇论文的标题、年份、chunk 数、标签和结构化快照组织在一起， 便于快速理解这篇论文的研究类型、领域、方法和关键焦点。

  • 支持 Paper Snapshot、Saved Notes、Metadata、Files 多种视角。
  • 更适合论文阅读、笔记沉淀与结构化整理。
  • 可以把“看论文”转化成“提炼研究资产”。
证据问答

AI Research Assistant

右侧的 AI Research Assistant 强调 grounded answer，也就是回答必须来自检索到的 source chunks， 而不是无依据地生成。

  • 可以围绕当前论文提问，例如“这篇论文的核心贡献是什么”。
  • 支持调节 top-k chunks，控制证据召回范围。
  • 也支持“只检索证据”而不直接写回答。
综述支持

Literature Review

这部分更偏“综述辅助”：围绕指定 tags 和 paper limit，先构建上下文，再生成文献综述， 适合把分散论文整合成一段可写进报告或论文的综述文字。

  • 支持 generate literature review。
  • 也支持仅构建 litreview context。
  • 把“搜集文献”推进到“组织综述”。
写作辅助

Writing Workflow

第二张图里最关键的是写作区：研究主题、标题、焦点已经被自动整理成草稿输入， 这使网站从“读论文工具”升级成“研究写作工具”。

  • 可以直接生成 paper draft。
  • 支持导出 BibTeX、APA 和 workflow pack。
  • 非常适合论文前期构思和材料整理。
导入导出

Import / Export 工作流

从底部的 Import New PDFs 到右侧多个导出按钮，这个工作台表达的是一条完整链条： 导入论文、切 chunk、做问答、做综述、做草稿、再导出学术写作材料。

  • 不是只展示结果，而是支持研究过程。
  • 能直接支撑航空方向的文献阅读和论文准备。
  • 和第二部分的航空地图形成“研究 - 系统”闭环。

第二部分：航空地图的展示重点

可以从四个层面理解这个项目：

1. 数据展示：地图上同时呈现航班轨迹、当前位置与样本覆盖范围
2. 时间交互：支持按时间轴回看空域变化，并进行播放控制
3. 状态监控：展示航班数量、轨迹点数和当前时间窗口
4. 预测功能：为选中的航班叠加未来轨迹，增强解释性和演示效果
因此，这一部分的重点不是单纯“有一张地图”，而是地图如何作为界面，把轨迹、时间和预测能力组织成一个完整的展示系统。

航空地图部分的系统组成

这一部分不再展开开发过程，而是聚焦观众真正能看到和理解的系统结构：数据、地图交互、预测模块与状态面板分别承担什么角色。

Module 01 · 数据层

高质量航班样本为地图提供基础输入

地图展示依赖结构化的轨迹点数据，每个点都包含经纬度、高度、速度、航向和时间戳， 这些信息共同决定了轨迹在地图上的形状与时间变化。

  • 样本数据适合用 Polyline 直接绘制轨迹。
  • 时间字段使回放与时间轴控制成为可能。
  • 速度与航向信息则为预测与状态解释提供基础。
Module 02 · 地图交互

时间轴、底图切换与航班列表共同构成主交互

航空地图的核心体验不只是“把线画出来”，而是让观众可以通过播放、暂停、拖动时间轴和切换底图， 观察空域状态的变化过程。

  • 底图可以在深色、地形、卫星等模式间切换。
  • 航班列表与地图轨迹联动，便于聚焦特定航班。
  • 时间轴让空间信息变成带时间维度的可视化叙事。
Module 03 · 预测功能

选中航班后，可叠加未来轨迹预测结果

预测模块让地图不仅能回看历史轨迹，还能对未来几步位置进行估计，从而增强项目的分析性和演示效果。

  • 模型基于历史轨迹序列推测未来位置与速度。
  • 结果在地图上以另一条轨迹线叠加展示。
  • 这种设计让预测结果与真实历史轨迹能够直观对比。
Module 04 · 状态面板

侧边信息区提供面向观众的解释入口

地图左侧的数据状态、时间范围和控制按钮，使观众不需要阅读代码也能快速理解当前页面正在展示什么。

  • 显示活跃航班数、轨迹点数和数据时间窗口。
  • 提供播放、重置、速度调节和预测控制按钮。
  • 使地图既是可视化界面，也是讲解界面。

航空地图的主要功能

从观众视角出发，航空地图最值得关注的是它最终在页面上提供了哪些功能，以及这些功能分别服务于怎样的展示目的。

可视化

动态展示航班轨迹

页面会把每架飞机的轨迹画成折线，并高亮当前位置。相比纯列表，地图能更直观地呈现飞行方向、分布密度和覆盖区域。

  • 适合展示航班空间分布。
  • 能够突出轨迹延展方向。
  • 更容易进行讲解和比较。
回放

按时间回看空域变化

时间轴允许拖动到任意时刻，也可以播放、暂停和调速。它把静态轨迹转换成带时间维度的动态过程。

  • 适合做时序演示。
  • 能观察航班出现与移动过程。
  • 提升地图的叙事能力。
预测

为选中航班叠加未来轨迹

预测功能使地图不只停留在历史展示，还能对未来轨迹给出估计，从而增强研究分析和演示效果。

  • 支持多步预测。
  • 与历史轨迹形成直观对比。
  • 体现项目的分析能力。
监控

同步显示航班数、时间范围和状态信息

侧边状态区把活跃航班数、时间窗口、轨迹点数等信息同步呈现，让观众更容易理解当前画面所对应的数据状态。

  • 增强页面解释性。
  • 辅助汇报讲解。
  • 让地图更像完整系统界面。
Hugo + Leaflet

多底图切换

深色、地形、卫星等不同底图提供了不同的观看语境，使同一批轨迹数据可以从多种地理背景中观察。

  • 适合不同展示需求。
  • 有利于强调轨迹或地理环境。
  • 提高观感与表达层次。
扩展

可继续扩展为空域分析工具

这套地图界面不仅适合当前展示，也为后续加入实时数据流、热力图、机场分析和异常检测预留了空间。

  • 适合继续做研究扩展。
  • 适合拓展成更完整的数据分析平台。
  • 具备持续演化潜力。

图 4：预测轨迹在页面上的展示方式

用户选中航班后，前端会把最近一段轨迹送进 /api/predict， 返回未来 1-10 步坐标，再把结果以另一种线型叠加到地图上。 这也是航空地图部分里最像 AI 应用的一块。

对话最终沉淀成了可复现命令

conda activate adsb

# 1. 构建 Clean 层
nohup python -u scripts/build_clean_adsb.py > logs/build_clean_full.log 2>&1 &

# 2. 生成质量报告

# 3. 导出地图样本
python -u scripts/export_map_sample.py

# 4. 训练 LSTM 模型（修复 float32 标准化后）
nohup python -u scripts/train_trajectory_model.py \
  --max-windows 5000000 --epochs 50 --batch-size 256 --lr 0.001 \
  > logs/train_full_v2.log 2>&1 &

# 5. 本地接入
hugo

航空地图最终能做什么

它不是单一视图，而是一个围绕航空轨迹数据构建的交互式分析入口。你可以把它理解成“以地图为界面的航迹监控系统”。

可视化

动态展示航班轨迹

页面会把每架飞机的轨迹画成折线，并高亮当前所在位置。相比纯表格，地图能瞬间看出航班的大致方向、 分布密度和覆盖区域。

回放

按时间回看空域变化

时间轴允许拖动到任意时刻，也可以播放/暂停、调速度。它把一小时窗口里的轨迹变化变成了可回放的过程， 适合做课程展示和轨迹讲解。

预测

给选中的航班叠加未来轨迹

这一步把 AI 真正接进了地图交互。用户不是只看历史，而是可以点选航班，让模型预测它接下来怎么飞。

监控

同时显示航班数、更新时间和轨迹点数

地图左侧的状态卡片让页面具备监控面板的感觉。它不仅告诉你“有什么”，还告诉你“现在系统正在处理多少东西”。

图层

切换底图来观察不同语境

深色主题适合强调轨迹，地形图和卫星图更适合解释区域位置。多底图支持让同一批飞行数据在不同表达里切换。

扩展

还能继续长成更强的空域分析工具

项目总结里已经留出后续方向：实时数据流接入、机场进出港分析、空域拥堵热力图、异常行为检测和 Transformer 模型升级。

航空地图部分的技术亮点

除了功能层面的展示，这个项目在技术设计上也有几个值得单独强调的亮点。

数据质量

大规模 ADS-B 数据经过质量筛选后再进入展示层

地图展示的数据并不是简单堆叠原始记录，而是先经过位置、时间、速度、航向等条件筛选，从而保证轨迹更稳定、更可信。

时间维度

空间信息和时间轴被放到同一个交互体系中

很多地图只能看位置，而这里的时间轴让空域变化成为真正可播放、可暂停、可调速的动态过程。

预测模块

预测结果直接回到地图界面中呈现

未来轨迹不是停留在后台模型中，而是直接以可见路径叠加到页面上，使模型能力变成观众可以直观看到的功能。

界面组织

地图区与控制区形成清晰的展示层次

地图主视图负责空间表达，侧边控制区负责解释、筛选和操作，两者分工清楚，适合用于汇报和演示。

多底图

同一批轨迹数据可以在不同地理语境下观察

不同底图强化了不同观看重点，例如深色图强调轨迹线，地形图和卫星图更有利于解释区域位置。

结果

最终呈现的是一个适合讲解的完整系统

这个项目既能展示轨迹数据本身，也能展示预测与交互能力，因此不仅适合作业展示，也适合作为后续研究与扩展的基础界面。

两个项目分别面向研究支持与系统展示，但都围绕航空主题展开，因此放在同一份报告里能够形成清晰互补。
